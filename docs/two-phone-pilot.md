# RIVO — вътрешен тест с два телефона

## Цел и обхват

Пътник изпраща заявка от един телефон. Шофьор с отделна сесия я вижда, приема и променя състоянието ѝ. Пътникът вижда тези промени и след презареждане.

Тестовият поток е на `/pilot`. Основният дизайн и демонстрационните екрани са на `/`.

Поддържани състояния: `waiting → accepted → arrived → in_progress → completed`. Пътникът може да откаже преди старта; шофьорът може да откаже свой приет курс преди старта. Неприета заявка изтича след 10 минути. Един участник има най-много един активен курс.

Цените са **тестови**: City 26 €, Premium 34 €. Определят се на сървъра и засега не зависят от маршрута. Плащания не се обработват. Пътникът и автомобилът са данни, въведени от тестовите участници; проверка на лиценз и одобряване на шофьори предстоят.

## Активиране в Preview

1. Свържи Vercel проекта `rivo-app` с **отделна Neon Postgres база за вътрешни тестове** чрез Marketplace → Storage → Neon. Първо провери плана и условията. Свържи я към **Preview**; използвай отделен ресурс за бъдеща реална услуга.
2. В Preview настрой само на сървъра:
   - `DATABASE_URL` — автоматично от Neon интеграцията.
   - `RIVO_PILOT_CODE` — непредвидим код с поне 16 символа. Този код допуска тестовите участници и до двете роли. Създава се в настройките, не в GitHub и не като `VITE_` променлива.
3. Свържи локалния checkout с правилния Vercel проект, изтегли Preview средата в игнориран `.env.local` и провери наличието на ключовете, без да отпечатваш стойности.
4. След проверката на свързването и средата изпълни `npm run db:migrate:pilot`. Миграцията добавя само таблиците и индексите с префикс `rivo_pilot_`; може да се изпълнява повторно. Тя не се изпълнява автоматично при build или при потребителска заявка.
5. Публикувай Preview от работния клон. Отвори `/api/pilot?action=session`: при готова конфигурация отговорът е JSON с `participant: null`. След това отвори `/pilot` на двата телефона.

Самата връзка на Neon с ChatGPT **не** добавя автоматично `DATABASE_URL` във Vercel. Свързването на базата, настройката на средата и миграцията трябва да бъдат потвърдени отделно. Тестовият сървър от `scripts/pilot-test-server.mjs` използва локален PGlite само за автоматизираните тестове и не се публикува като API.

## Проверка от два телефона

1. На първия отвори същия Preview адрес с `/pilot?role=customer`, въведи име и тестовия код.
2. На втория отвори `/pilot?role=driver`, въведи име, автомобил, номер, **същата категория като заявката** и тестовия код.
3. Пътникът избира взимане, дестинация и категория и натиска „Изпрати заявка“.
4. Шофьорът вижда заявката и натиска „Приеми заявката“. До следващото обновяване пътникът вижда името и автомобила му.
5. Шофьорът последователно натиска „Пристигнах“, „Стартирай курса“ и „Завърши курса“. Двата екрана отразяват едно и също състояние.
6. Провери презареждане на всеки телефон, отказ, липса на шофьор и опит за приемане от втори шофьор. При липса на връзка трябва да има видимо съобщение; автоматично приемане няма.

Обновяването е на около 2 секунди при отворен екран. Излизане с активен курс е блокирано, за да се запази достъпът до него. Сесията трае 24 часа; смяната на тестовия код обезсилва съществуващите сесии.

## Локални проверки

```bash
npm ci --ignore-scripts
npm test
npm run build
npx playwright install chromium --only-shell
npm run test:browser
```

API тестовете изпълняват действителния SQL върху PGlite (PostgreSQL). Browser тестовете ползват два независими cookie контекста и същия handler. Те не изискват достъп до реалната Neon база и не потвърждават сами по себе си работата във Vercel.

За проверка на изрично избрана изолирана Preview среда задай `RIVO_E2E_BASE_URL` и зареди `RIVO_PILOT_CODE` безопасно от локален игнориран env файл. Тогава browser тестовете използват този адрес и не стартират локалния PGlite сървър. Използвай само тестови участници и тестовата база.
